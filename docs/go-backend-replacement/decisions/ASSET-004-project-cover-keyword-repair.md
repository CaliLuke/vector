# ASSET-004: Repair PROJECT_COVER duplicate-keyword failures

Status: Approved source correction, backed by immutable and corrected Django recordings. The original fixtures remain unchanged. The corrected behavior is scoped to project collection upload and workspace duplicate requests whose asset type is `PROJECT_COVER`.

The original Django handlers pass `project_id` explicitly and also expand `get_entity_id_field()` for `PROJECT_COVER`, which contains `project_id`. Python rejects the duplicate keyword before the handler inserts a row. The preserved source recordings show HTTP 500 and no database or storage changes for the original matching, mismatched, foreign, and missing-entity requests.

For `POST /api/assets/v2/workspaces/{slug}/projects/{project_id}/`, a nonempty `entity_identifier` must equal the project in the route. A matching identifier creates the pending cover asset and returns the normal presigned upload response. A missing or different identifier returns HTTP 400 with `{"error":"Entity project must match the requested project.","status":false}` before any write or storage access. The resulting asset stays associated with the route project and workspace.

For `POST /api/assets/v2/workspaces/{slug}/duplicate-assets/{asset_id}/`, `entity_id` is required. An optional `project_id` must match it. The effective project must exist in the requested workspace; an explicit mismatch returns HTTP 400 with the same error body, while a missing project in that workspace returns HTTP 404 with `{"error":"Project not found"}`. A valid same-workspace entity works with or without `project_id`; the duplicate is associated with that project and the workspace from the route. Validation happens before copying the object. This decision adds no project-membership requirement.

The second-wave source recording also covers a project whose row exists but has `deleted_at` set. The temporary corrected source uses `Project.objects`, which excludes tombstoned projects: collection upload returns HTTP 404 with `{"error":"Project not found","status":false}`, and duplicate returns HTTP 404 with `{"error":"Project not found"}`. Both reject before a FileAsset insert, upload key creation, or object copy. The original preserved source still reaches its existing duplicate-keyword HTTP 500 on those two PROJECT_COVER requests. A separate ordinary workspace-logo duplicate with an explicit tombstoned `project_id` returns HTTP 404 before any effects.
