# ASSET-003: Keep a duplicate pending when its S3 copy fails

Status: Corrected Django evidence is recorded and the focused Go replay passes. Full family release proof remains pending; see the assets proof ledger.

`POST /api/assets/v2/workspaces/{slug}/duplicate-assets/{asset_id}/` creates a new `FileAsset` row and copies the source object to a new key. The original handler ignores the return from `S3Storage.copy_object` and marks the new row uploaded even when S3 reports `NoSuchKey`. The immutable source fixture, [workspace-asset-duplicate-copy-missing-source-still-marks-uploaded](../../../../apps/go-api/internal/parity/testdata/fixtures/assets_lifecycle/workspace-asset-duplicate-copy-missing-source-still-marks-uploaded.json), records the false-success response: HTTP 200 with an `asset_id`, an uploaded row, and no destination object.

The replacement returns HTTP 500 with `{"error":"Something went wrong please try again later"}` when the copy fails. It leaves the newly created row in place with `is_uploaded=false`, preserves the copied storage metadata, and emits no durable work. The source and destination S3 objects remain absent. A successful copy continues through the existing upload completion behavior.

The corrected behavior was measured with one narrow temporary change in `plane/app/views/asset/v2.py`: check the `copy_object` result and return the existing generic 500 response when it is `None`; update `is_uploaded` only after success. The recorder now identifies the one new FileAsset row when the response has no `asset_id`, then records its persisted state and object-store state. It still uses the response ID for successful duplicate requests. The observer change is retained in [its exact patch](evidence/ASSET-003-recorder-observer.patch). The complete corrected record is retained separately in [the evidence JSON](evidence/ASSET-003-copy-failure-corrected-source.json) and its executable copy under `apps/go-api/internal/parity/testdata/fixtures/assets_lifecycle_decisions/`. The temporary source diff and hashes are in [the evidence patch](evidence/ASSET-003-copy-failure-source.patch) and [provenance](evidence/ASSET-003-copy-failure-provenance.json). The original canonical fixture remains unchanged. The corrected fixture uses the same request, authenticated principal, seed, unchanged database baseline, zero effects, and absent S3 objects; its only intended differences are the response and the new row's `is_uploaded` value in the database and matching external state.
