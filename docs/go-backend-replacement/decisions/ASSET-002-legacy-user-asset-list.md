# ASSET-002: Serialize existing user assets as a list

Status: Original failure and corrected Django response recorded; Go parity is pending.

`GET /api/users/file-assets/{asset_key}/` filters FileAsset rows by the exact storage key and the authenticated creator. When a matching row exists, `UserAssetsEndpoint.get` passes the resulting QuerySet to `FileAssetSerializer` without `many=True`. The serializer attempts to read the QuerySet's nonexistent `asset` attribute, and the endpoint returns HTTP 500 with `{"error":"Something went wrong please try again later"}`. The source run in `/tmp/plane-assets-family/focused-repair4.log` confirms this branch after the fixture's creator was correctly persisted. Its traceback identifies `plane/app/views/asset/base.py:74`.

The replacement returns HTTP 200 with `{"data":[...],"status":true}`, serializing the matching rows with the same FileAsset fields and request context. This is the behavior produced by adding only `many=True` to that serializer call, and it matches the existing workspace asset endpoint's list shape. Exact-key matching, authenticated-creator scoping, default-manager filtering, ordering, and field values remain unchanged. Missing or nonowned keys retain the existing HTTP 200 response `{"error":"Asset key does not exist","status":false}`. The read introduces no database writes, queue messages, cache changes, or object-store changes.

Keep the original failing source fixture immutable. Record the response from the narrow `many=True` correction separately, restore the original source file, and verify its digest before further baseline recording. Go replay may apply only that named, exact response transition. It must compare all other fixture observations unchanged. The corrected Allow header is governed by [ASSET-001](ASSET-001-invalid-methods.md); this decision does not make the unsupported POST on the identifier path valid.

Before activation, prove the existing-owner success, nonowner/missing result, and unchanged side effects against Go. A test that returns the missing-key response for the seeded owner's asset does not cover this repair.
