# Shared work-item query language

## Summary

PQL belongs to Vector's work-item query boundary. HTTP and MCP must execute the same predicates against the same authorized candidate set. MCP must not translate PQL into client-side filtering or publish a reference for language that cannot execute.

This design establishes the parser and the scalar, relationship, member, and body query boundaries below. It does not settle the missing milestone or teamspace models and does not complete VEC-12 or VEC-22. The accepted target remains the full language in the [pinned reference](https://github.com/makeplane/plane-mcp-server/blob/dc7cfd9f3c305891909e2372f0cc507291353801/plane_mcp/pql_reference.py). The current execution surface below is explicitly smaller than that target; it adds no MCP action or reference-tool registration.

## Problem statement and current state

Before this change, `internal/workitems/list.go` rejected all API `pql` and structured `filters` inputs. Application filters already use `internal/issuequery`; custom-property filtering additionally uses authorized property-discovery snapshots in `internal/workitemtypes`. Reimplementing those responsibilities inside MCP would produce different permission and query behavior.

## Proposed design

`internal/issuequery` owns PQL syntax and parameterized predicates. `internal/workitems` owns authorization, candidate selection, transaction scope, pagination, and projection. The compiler accepts an actor ID, one request-time instant, and a validated requester timezone. It emits only a predicate over the existing `issue` and `project` aliases plus bound arguments. It never selects rows, creates SQL identifiers from user input, performs authentication, or widens the candidate set.

The parser consumes the entire input before compilation succeeds. Each standalone predicate counts as one condition. Every expression is compiled, including logically unreachable branches. Unknown names, unavailable capabilities, invalid operands, and trailing tokens return HTTP 400 without executing the item query. Errors identify the byte offset and category; they do not echo literal values or query text. Compiler failure leaves the caller's argument slice unchanged.

| Capability         | Foundation execution                                                                      | Rejection and remaining scope                                                                                         | Default and equivalence                                                                                 |
| ------------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Logic              | Parentheses, NOT, AND, OR; precedence in that order                                       | More than five conditions; malformed or trailing syntax                                                               | Blank PQL adds no predicate; count each comparison once, including IN and BETWEEN                       |
| Strings            | `priority`, `title`, `id`                                                                 | Unknown fields; invalid priority enum; ordering on strings                                                            | Exact case-sensitive equality; `~` uses literal case-insensitive containment, except `id` uses a prefix |
| Booleans           | `isDraft`, `isArchived`                                                                   | Quoted booleans; non-boolean operands                                                                                 | Bare true/false; predicate calls are equivalent to equality with true                                   |
| Dates              | `dueDate`, `startDate`, `createdAt`, `updatedAt`                                          | Invalid calendar values, date arithmetic, wrong function arity                                                        | Requester timezone; one captured instant for all relative functions                                     |
| UUIDs              | `project`, `createdBy`                                                                    | Names instead of UUIDs; function on an incompatible field                                                             | UUID normalization; `createdBy = currentUser()` uses the authenticated actor                            |
| Operators          | `=`, `!=`, IN, NOT IN, null tests; text empty tests and `~`; date comparisons and BETWEEN | Operator/type mismatches; empty lists; NULL as a comparison operand                                                   | BETWEEN is inclusive; both `a AND b` and `(a, b)` range forms parse                                     |
| Existing API lists | Apply PQL before count and pagination, including archived lists                           | Structured `filters` remain rejected; any nonempty external identity parameter combined with nonblank PQL is rejected | Absent PQL preserves existing list and external-identity behavior                                       |
| Remaining PQL      | Further fields and functions are defined below                                            | Custom properties, milestones and teamspaces still require domain integration                                         | Reject explicitly; never drop an unsupported condition                                                  |
| MCP surface        | None added by this foundation                                                             | Core query actions and `get_pql_reference` remain unadvertised until their complete contracts execute                 | Auth/protocol variants eventually share the same application entrypoint                                 |

An independent behavioral review and focused re-check found the initial contract ready after making function arities and DST resolution explicit.

The compiler's field and function definitions are the executable authority for this subset. Names are case-sensitive; logical/operator keywords are case-insensitive. There are no aliases. The pinned reference remains the target for subsequent additions, not an assertion of current support. Existing structured-filter semantics are unchanged.

## Detailed behavior

### Grammar and limits

Values are JSON double-quoted strings, bare booleans, decimal numbers, or function calls. Fields use their documented camelCase names; custom-field syntax can be parsed but must be rejected until an authorized property resolver is connected. Single-quoted strings, comments, and arbitrary expressions are rejected. No expression is evaluated as SQL or source code.

The input is limited to 16 KiB, nesting to 64 levels, and explicit lists to 256 values. These are resource bounds in addition to the five-condition language limit. Oversized inputs fail rather than being truncated. Lists contain scalar values, not nested lists. Function argument lists use the same bound.

Scalar equality, inequality, ordering, and negation preserve PostgreSQL's three-valued logic: a missing scalar is unknown and does not match even under NOT. Null tests are the way to select missing values. `IS EMPTY` means an empty string, and is different from `IS NULL`; `IS NOT EMPTY` excludes null. For priority, the string `none` is a real enum value, not SQL NULL. Booleans support equality/inequality and null tests, not IN or ordering. Dates support comparison, BETWEEN, and null tests, not IN or text operations. UUIDs support equality/inequality, IN/NOT IN, and null tests. Strings support equality/inequality, IN/NOT IN, null/empty tests, and containment; priority allows only its enum values and does not allow containment or empty tests.

`id` is the project identifier, a hyphen, and the item's decimal sequence ID. Equality compares that complete identifier; containment uses a prefix. `title` uses the item name. Date fields map to `target_date` and `start_date`; timestamp fields map to `created_at` and `updated_at`. Existing route rules for deleted, archived, draft, or epic items remain candidate restrictions: a PQL predicate never overrides them.

### Time

Empty timezone means UTC; an invalid nonempty timezone is an error. Date literals use `YYYY-MM-DD`; timestamp fields additionally accept RFC 3339 timestamps. Calendar years must be between 1 and 9999, including function results. A date literal on a timestamp field means midnight in the requester timezone. Comparisons do not silently expand equality into a day range.

The initial function allowlist is `now`, `today`, `startOfDay`, `endOfDay`, `startOfWeek`, `endOfWeek`, `startOfMonth`, `endOfMonth`, `startOfYear`, and `endOfYear` with zero arguments; `daysAgo`, `daysFromNow`, `weeksAgo`, `weeksFromNow`, `monthsAgo`, and `monthsFromNow` with one integer argument; `currentUser()` only as a value for `createdBy`; and standalone zero-argument `isDraft()` / `isArchived()`. The extensions below add their explicitly listed functions. All other function names and arities are rejected. Value functions are not standalone predicates.

`now()` is the captured instant. `today()` and `startOfDay()` are local midnight. Weeks begin Monday. Starts of week/month/year are local midnight; ends are one microsecond before the next period starts, matching PostgreSQL timestamp precision. Relative day/week/month functions apply calendar shifts to the captured local instant. Month shifts clamp the day to the destination month's final day. Integer offsets are nonnegative and at most 10,000; fractional offsets and other arguments are rejected. On date fields, date functions use the resulting local calendar date. DST therefore changes elapsed duration without changing calendar boundaries. For a computed civil time in a clock gap, reject the query rather than silently normalizing its date or clock time. For a fold, use the earlier instant. The same rule applies to literal local midnight and calendar boundaries. Relative shifts retain the local clock time and microseconds; all timestamp operands are truncated to microseconds. PQL timezone errors do not change the legacy serializer’s UTC fallback behavior.

### Routing and safety

```text
authorize the existing API request
reject structured filters and conflicting external-identity/PQL mode
parse the whole PQL expression with resource limits
compile every leaf with typed values and bound parameters
AND the compiled predicate with the authorized candidate restrictions
count and page those candidates through the existing list path
project through the existing HTTP serializer
```

The initial integration does not authorize MCP to call the current general list path: that path still needs immutable workspace binding and a consistent authorization/projection snapshot before MCP core reads are registered. Domain resolvers for relationships and custom properties must use that same snapshot and mask foreign or invisible references under both positive and negative predicates. The existing property-filter true/false/unknown model is the relevant boundary; this design does not replace it.

## Proof obligations

- Precedence, grouping, both range forms, and five-condition accounting select the intended records; invalid branches cannot be hidden behind OR or NOT.
- Literal quotes, SQL-looking text, and LIKE wildcard characters remain data. Failed compilation cannot partially modify query arguments.
- Date boundaries hold across DST, leap years, month-end shifts, and non-UTC requests.
- Public repository lists filter before count and page limits, preserve legacy behavior without PQL, and never return another project's items because a predicate names that project.
- Every currently executable capability has a public compiler or real PostgreSQL repository proof. The parity tracker continues to show all unimplemented actions; syntax support alone never changes its counts.

## State and project relationship extension

These executable additions use the existing compiler and API list path. These definitions are authored in `internal/issuequery`, execute in the candidate query's snapshot, and add no MCP registration. Existing non-PQL filters and projections retain their behavior. Missing relationships never trigger an unscoped lookup or a distinct existence error.

| Capability          | Supported and defaults                                                                                 | Rejected / deferred                                                                                  | Equivalence and proof                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| State               | `state` UUID and `stateGroup` enum: backlog, unstarted, started, completed, cancelled                  | Invalid enum, name in UUID position, ordering, containment, empty tests                              | Resolve a nondeleted state in the item's project and workspace; missing, deleted or foreign state becomes SQL NULL, including under NOT            |
| Type                | `type` UUID; a nondeleted workspace type remains readable when paused or not imported into the project | Names and invalid UUIDs; ordering, containment, empty tests                                          | Matches the workspace type identity catalog; foreign/deleted types become SQL NULL                                                                 |
| Project collections | `label`, `cycle`, `module`: UUID equality, inequality, IN/NOT IN, null/empty tests                     | Ordering, containment, BETWEEN                                                                       | A member requires a nondeleted bridge and target, with both owned by the item's project and workspace; duplicate bridges never multiply candidates |
| State lists         | `stateGroup IN/NOT IN openStates()`, `closedStates()`, `activeStates()`                                | Arguments, scalar use, nested calls, wrong field, mixing a list function into an explicit value list | Same result as the documented explicit enum list, including SQL NULL behavior                                                                      |
| Cycle lists         | `cycle IN/NOT IN activeCycle()`, `completedCycles()`, `upcomingCycles()`                               | Arguments, scalar use, wrong field, nested or mixed lists                                            | Compare cycle endpoint calendar dates in the requester timezone with the one captured request date; boundary, timezone and missing-endpoint proofs |
| Predicates          | Zero-argument `hasNoLabel`, `isOverdue`, `isEpic`, `hasStartAndDueDates`, `isIntake`                   | Any argument; predicate as a comparison value                                                        | Same ownership, missing-value and calendar rules as the corresponding fields; one condition per call                                               |

For scalar state/type fields, equality, inequality, IN/NOT IN and null tests use the existing scalar rules. State-group functions expand to the pinned enum sets. A valid but nonexistent UUID is data, not a validation failure.

For collections, `= x` and `IN (...)` mean at least one visible member matches. `!= x` and `NOT IN (...)` mean no visible member matches; they include an empty collection. `IS NULL` and `IS EMPTY` both mean no visible members, and their negations mean at least one. NOT of a collection predicate is therefore two-valued. Deleted, foreign, dangling, or incorrectly owned bridges are absent under all operators, including negative and empty tests. Archived cycles and modules remain relationship targets until deleted; archiving does not remove an item's recorded relationship. Function-based cycle filters use the same target set as explicit cycle IDs.

Cycle date functions use `start <= today <= end`, `end < today`, and `start > today` respectively, comparing calendar dates in the requester timezone. The compiler binds the already resolved start/end-of-day instants using the same gap/fold and microsecond rules as scalar date functions; PostgreSQL does not independently resolve timezone names. A null required endpoint does not match that function; completed needs only end, upcoming needs only start, active needs both. Multiple active cycles are a set, not an error. A cycle's own timezone does not override the request timezone. Direct list-function syntax is required: `cycle IN activeCycle()`; `cycle = activeCycle()` and `cycle IN (activeCycle())` fail. Explicit UUID lists remain unchanged.

`hasNoLabel()` is exactly `label IS EMPTY`. `hasStartAndDueDates()` requires both dates to be nonnull. `isOverdue()` is `dueDate < today() AND stateGroup IN openStates()` and preserves scalar SQL NULL behavior, including under NOT. `isEpic()` tests the resolved type's epic flag; a missing type is unknown, not false. `isIntake()` means at least one nondeleted `intake_issues` bridge to a nondeleted intake, with bridge and intake owned by the item's project and workspace. Intake status does not remove the relationship. It is independent of the state group and does not override route candidate exclusions.

Proofs must include positive, negative, NOT and empty/null queries over foreign and deleted targets and bridges, plus count and pagination with multiple relationships.

## Item, member, and body extension

These additions remain in the same compiler and authorized API candidate query. They do not register incomplete MCP core actions or change existing non-PQL filters. Every lookup is correlated to the candidate item's workspace in the same SQL statement. A syntactically valid but missing, deleted, foreign, or inaccessible target contributes no visible relationship; negative predicates cannot distinguish these cases. Actor-dependent expressions require a valid actor UUID even in a logically unreachable branch.

| Capability           | Supported/default                                                                                                             | Rejected/deferred                                                                             | Equivalence/proof                                                                                                                                                                                    |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hierarchy            | Zero-argument `isTopLevel`, `isSubWorkItem`, `hasChildren`                                                                    | Arguments; comparison-value use; recursive ancestry                                           | Top-level means no visible parent; sub-item means a visible parent; children means at least one visible direct child. Shared related-item visibility, including guest and revocation proofs          |
| Named item relations | `childOf`, `parentOf`, `linkedTo`, `blockedBy`, `blocks`, `duplicateOf`, each with one quoted UUID or identifier              | Titles, invalid identifiers, non-string/wrong arity, recursive traversal                      | Direction and bridge ownership below; invisible targets are absent under both positive and NOT queries; duplicates never inflate count or pagination                                                 |
| User collections     | `assignee`, `mention`, `subscriber` with the collection operators defined above; `hasNoAssignee()` equals `assignee IS EMPTY` | Ordering, BETWEEN, text operators; arguments to the predicate                                 | Live owned bridge plus a readable roster identity; inactive target identities are retained, deleted memberships are not                                                                              |
| Current user         | `currentUser()` scalar for `createdBy`, `assignee`, `mention`, `subscriber`, including explicit scalar lists                  | Arguments and other fields                                                                    | Uses the authenticated actor UUID; no identity inferred from names or email                                                                                                                          |
| User list functions  | `workspaceMembers()` and `membersOf("project:<uuid>")` in direct IN/NOT IN for the four user fields                           | Wrong arity/prefix/value/field, scalar or nested-list use; teamspace variant remains deferred | Only readable rosters in the item's workspace participate; empty/inaccessible roster is an empty set, not a distinct existence error. Scalar `createdBy` NULL remains unknown even with an empty set |
| Body text            | `text` supports the same string operators as `title`                                                                          | Non-string values and ordering                                                                | Joins nonempty title and main plain-text description with one newline; both null yields NULL, otherwise both empty yields empty string. Custom rich-text properties are not part of this field       |

`internal/issuequery` owns the pure related-item SQL helpers; `internal/djangoapi` retains delegating functions for existing callers. Their existing visibility rule is unchanged: the related item is published and nondeleted, in the candidate workspace, with a live owning project/workspace and current workspace/project memberships. Contributors/admins can read it; guests require ownership or project-wide guest visibility. Archived items, archived projects, and triage items can remain related targets under that existing rule, while root candidate exclusions remain authoritative. Drafts never become related targets. `isTopLevel()` and `isSubWorkItem()` use the same masked parent as serialization. `hasChildren()` and item relation calls are two-valued existence predicates, not recursive queries.

Identifiers use the last hyphen to separate a nonempty, case-sensitive project identifier from one or more ASCII decimal digits. Leading zeros normalize numerically; signs, whitespace and non-ASCII digits are rejected. Sequence operands are bound as decimal strings, allowing the parser's input limit rather than an int64 conversion to bound them. UUIDs normalize through the existing UUID parser. Identifier resolution also requires a live owning project in the current workspace; the existing partial unique project identifier index provides uniqueness. No user-controlled identifier becomes SQL syntax.

`childOf(x)` tests the candidate's direct parent; `parentOf(x)` tests whether the visible target's direct parent is the candidate. `linkedTo(x)` selects `relates_to` bridges in either direction. `duplicateOf(x)` selects `duplicate` bridges in either direction, matching the shared relation reader. Canonical `blocked_by` storage puts the blocked item in `issue_id` and its blocker in `related_issue_id`: `blockedBy(x)` uses that direction, `blocks(x)` reverses it. Other stored relation kinds do not match these calls. A bridge must be nondeleted, belong to the candidate workspace, and record either endpoint's project; the existing writer retains the originating project's ID when reversing blocking endpoints. A third project's bridge is absent. Both endpoints must satisfy the shared visibility rule; malformed self-links have no special meaning beyond these direct predicates.

User collection bridges must be nondeleted and match the item ID, project and workspace. A target user is a readable identity if either (a) the actor may read the item's project roster and a nondeleted project membership links that user to the item's project/workspace, or (b) the actor may read the workspace directory and a nondeleted workspace membership links the user to that workspace. Branch (a) uses exactly the actor admission rule for `membersOf` below, including live project/workspace, live actor user, active/nondeleted actor project membership and active/nondeleted actor workspace membership with role 5, 15 or 20. Both branches recheck their actor guard in the same correlated SQL lookup; earlier request authorization is not a substitute. The user row must exist. Target membership/user inactivity does not erase recorded relationships; both existing roster readers retain these identities. This is identity visibility, not permission to assign or notify an inactive member.

`workspaceMembers()` requires the actor's live user and active, nondeleted workspace membership with role 15 or 20; it selects existing users with nondeleted memberships in that workspace, including inactive members. `membersOf("project:...")` requires a live project/workspace in the item's workspace, the actor's live user and active/nondeleted project membership, and active/nondeleted workspace membership with role 5, 15 or 20. It selects existing users with nondeleted project memberships in that project/workspace, including inactive members. Archived projects remain readable rosters, as in the shared member reader. Missing or unreadable rosters produce an empty set under both IN and NOT IN. These queries do not execute separate unbound roster requests or widen the root candidate set.

Proofs must include membership revocation, guest ownership/view-all transitions, foreign and deleted endpoints/bridges, both relation directions, normalized identifiers, duplicate bridges, inactive/deleted member identities, inaccessible user lists under NOT, nullable creators with empty lists, main-description matching without custom-field matching, and preserved count/pagination before projection.

## Remaining domain decisions

Milestone and teamspace ownership, membership, archive behavior, and relationships require inspected domain designs before their resolvers exist. Property PQL requires an explicit mapping from the pinned property type/operator matrix into Vector's effective property catalog. Those are remaining work, not intentionally excluded full-parity features. The full reference tool must wait for all documented examples and resolver dependencies to work.
